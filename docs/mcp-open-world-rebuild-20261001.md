## 0. 为什么推翻视觉精修路线

v2/v3 证明了：在「器官拓扑图 + 实验室」这套框架里做减法，做不出来。因为问题不在皮，在骨——
**这套 UI 是给"开发者看系统"的，不是给"小白住进去"的。** 热力图、Betti 数、莫比乌斯、RRA
叙事全部回答的是"系统多厉害"，而小白只想知道三件事：**这是什么、它好不好、它能为我干什么。**

主人原话锚点：
- "一花一草一木，一叶一菩提" —— 每个模块都是世界里的活元素，可操控、可可视化
- "为小白提供更好的处理" —— 易用性是第一价值，不是第二价值
- "风动幡动，仁者心动" —— 世界要回应人的心意（交互原则）
- "初期模拟太空舱，随时间丰富" —— 世界有初始形态，会长大
- "self 要么界面出色，要么实用，要么好调试" —— self 必须三选一立住

## 1. 主题（一句话）

> **Open World = 你的 AI 助手住进的一座小园子。园子里每一棵树、每一盏灯、每一扇门，都是系统的一个能力：看得见、摸得着、说得清、办得成。**

- 定位：**不是仪表盘，不是第二套 DSH，是"能力的家"**。
- 小白视角：我打开一个世界，看到一座太空舱落在山水之间。舱里有灯（会话）、塔（任务）、湖（记忆）、门（回退）、桥（连接）。我点哪样，哪样就用白话告诉我它是谁、它现在怎么样、我能让它做什么。
- 与既有文档的关系：**OWIP 协议、ACL、事件环、进世界契约全部保留**（那是脊梁，不是皮）；被推翻的只是 L3 叙事层与 L2 的呈现层。
- "AGI/统一控制体"那些词：**首屏一律消失**，只允许出现在"舱内书阁"（高级页），且带"隐喻"标签。

## 2. 市面研究（学什么、不学什么）

| 参考 | 学到 | 不学 |
|------|------|------|

| Sentry/Datadog agent observability [1][5] | trace 是给调试者的，**不是给首屏的** | 首屏放 token/时延曲线 |
| 图扑水墨 3D（水墨大坝/国风车站/水墨数据中心）[6] | 严肃系统用水墨呈现已有成熟案例，"意境承载状态"可行 | 3D 组态的成本 |
| 国风 UI 五法：纹样组件、中国色、意象、大背景、古今排版 [7] | 设计语言骨架 | 大红大金的"喜庆国潮"（要的是**克制**） |

结论：我们做的东西（**个人 agent 的"可居住世界"+ 协议内核**）在这批产品里确实没有完全一样的——
它们都是"办公室/房间"（工业隐喻），没人做"山水园子"（东方隐喻），更没人把它做成 DSH 插件。
**差异化 = 科技中国风 + OWIP 协议内核 + dsh-self 园艺治理**，三者缺一不可。

## 4. 园子视图：一花一草一木 = 一能力一元素

世界初始形态 = **太空舱**（主人指定）：一座舱落在水墨山水间，舱体即"家"。
每个能力 = 世界里的一个**活元素**，元素三要素：**形（意象）· 名（一字中文+小字英文）· 气（状态）**。

| 元素（意象） | 能力（OWIP 节点/动作） | 气（状态如何画） |
|--------------|------------------------|------------------|
| 灯（窗中灯火） | 会话 sessions | 明灭=活跃数；暖=正常，暗=离线 |
| 塔（三层小塔） | 任务看板 task-board | 层数=队列深度；塔顶挂旗=有进行 |
| 湖（一弯湖水） | 记忆 hindsight | 水深=记忆量；涟漪=刚写入 |
| 门（舱门） | 回退 rewind | 门开=可用；门缝透光=有存档 |
| 桥（石梁） | 连接/第二屏 space | 桥通=peer 在线；桥断=未连 |
| 幡（门旁白幡） | 事件流 events | 幡应事而舞（见 §5） |
| 石（阶前磐石） | dsh-self 园丁 | 石上苔色=健康分 |
| 井（预留） | world-packs 世界包 | 井中无水=未装；井映月=可用 |

规则：
- **每个元素可点**：点 → 涟漪 → 浮出"名牌"（这是谁/现在怎么样/能干什么 ≤3 个动作，白话）
- 元素离线 = 灰 + 一句"怎么点亮"（沿用 howToEnable，禁点进空壳）
- 首屏元素数 **≤8**（舱里 7 个 + 预留 1 个），新能力先住"园外苗圃"，养熟了才入园
- 隐喻诚实：元素名牌角落有"喻"字角标（source=metaphor 制度化到像素级）

## 5. "仁者心动"：世界回应的三条法则（交互层）

主人原话"风动幡动，仁者心动"落地为三条可实现的交互法则（纯 2D canvas + CSS，无 WebGL）：

1. **风**（全局环境）：世界有常驻微风；**鼠标/指尖的移动就是心意**——移动越快，风越大，
   柳丝/幡/花瓣的偏角随鼠标速度变化（阻尼跟随，0.2s 响应，上限 15°）。静止时风自息。
   这是"心动则风动"。
2. **涟漪**（操作反馈）：点任何元素，墨色涟漪从触点扩散（Material 涟漪的水墨版，
   120ms 起、700ms 散），元素"应声"（轻微抬升+名片刻亮）。所有可操作处必有涟漪——
   "仁者心动"的最小单位。
3. **幡**（事件反馈）：世界发生事件时，门旁白幡**舞一次**，幅度=事件重要级（L0 微摆/
   L1 小舞/L2 大舞+落一瓣）。事件不落列表，落幡上；想细看，点幡 → "园径"（事件小径，
   竖向一列行书式时间线，最多 7 条，旧的入土）。

验收：这三条全部可用 60fps 纯 canvas2D 实现；**禁止**呼吸灯/扫描线/粒子过载（>200 粒子）。

## 6. 动作事件简化："三风"模型（核心难点的解法）

主人判断：动作事件过于复杂，难以落地。解法 = **把"事件系统"从图降回风**：

```
我起的风（action）   用户点了元素 → 涟漪 → 白话结果句（"信已放入信箱"）
世界的风（event）    系统自己发生 → 幡舞一次 + 一行白话（"任务 塔·三号 完成了"）
客的风（social）     他人/他机在世界里 → 窗上一盏客灯 + 白话（"第二屏 来看过"）
```

- 不再有事件图/因果链/状态机 UI。**因果与 trace 只存在 OWIP 数据层和 dsh-self 调试面**
  （给调试者的，不给首屏的——市面结论 [1][5]）。
- 每个 event 的 `kind` → 一个**视觉隐喻表**（固定 10 个，代码即文档）：
  message=风铃 / task=塔旗 / error=落枝 / health=月色 / memory=湖纹 /
  enter-world=开门 / leave-world=掩门 / peer=客灯 / pack=井纹 / notify=檐角风铃
- 实现：`snapshot.events[]` 与 `POST /action` 一行不改；只改 Client 渲染层。
  **动作事件"过于复杂"的根源在呈现，不在协议——协议保持 0.3-draft 不动。**

## 7. 聊天坞："信"

聊天不是面板，是**写信**：
- 输入区 = 一张信纸（浅色唯一例外，宣纸 #F4EFE6，墨字），位于园子下方居中，宽 60%
- 上方一排小圆钮 = 投递目标（沿用 v2 已定稿的"输入框上一排小按钮"）：
  世界(默认) / 信箱 / 任务塔 / 记忆湖
- 助手回信 = 从窗中递出的一张短笺（自动收拢，留"收信"小印可再展开）
- 语音/拖放/图片入口都在信纸右下角，图标用**纹样**（云纹/梅纹/山水纹），不用科技图标
- 技术：现有 chat-store 与投递机制 100% 复用，只换皮肤与容器

## 9. 如何向上延伸（含主人的服务器问题）

```
Phase 1  自己的园子（本地，本轮）
         舱 + 8 元素 + 信 + 三风。零新基础设施，OWIP 不动。
Phase 2  一屋两屏 → 世界服务器（买一台小 VPS 即可，2C4G）
         主人问"是否可以通过搭建服务器实现用户间交流"——可以，且很便宜，但只做三件轻事：
         ① presence（谁在园里：客灯） ② 事件中继（把"天气"分享出去：只发 kind+白话，
         不发数据） ③ 信箱中继（跨园传信，复用 outbox 密封）。
         数据最小化：世界状态不同步，各机各园，只共享"见闻"。Space ACL/令牌体系原样复用。
Phase 3  世界包（世界版插件市场）
         别人可以送"园子"：主题（雪夜/江月）、新元素（一座亭子=SSH 桥）、规则（节气皮肤）。
         装包走 dsh-self 收编：园丁验收 → 登记 capability-registry → 入园。
Phase 4  多世界（以后再说）
         多用户共建一座园 / 我的多个舱（工作舱/家舱）——协议在 OWIP 0.4 再谈。
```

**self 插件定位（主人问"它的独特功能是什么"）：self = 园丁。**
- 界面出色：园丁簿（一页：哪些器官活着/多健康/今天做了什么/一键复原基线）
- 实用独特：**收编**是它独有的活——外来插件想入园，必须园丁验收登记（inspect→wrap→
  声明权限→试种苗圃→入园）。open-world 是园丁的脸。
- 便于调试：trace/归因/组合校验只有园丁有钥匙（L3 宿主审计面，§万物即是插件 5.7）。
- 一句话：**open-world 是园子，self 是园丁；园子给小白住，园丁给自己信。**

## 14. 与控制台的结合（前厅后园）· 2026-10-01 定调

**主人判断**：园子只能算一个小的扩充点，不能当大点；主身必须是控制台。完全同意，且昨晚的插件本来就是那个控制台的胚胎——两者不是二选一，是**前厅后园**：
