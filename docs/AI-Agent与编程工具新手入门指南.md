## 1. 先建立整张地图

编者认为：把 2025–2026 年热起来的东西先按**层级**拆开，比死记品牌名更不容易晕。

| 层级 | 人话 | 典型名字 | 主要解决什么 |
|------|------|----------|--------------|
| **模型（LLM）** | 大脑 | GPT、Claude、DeepSeek、Gemini、Qwen、Kimi… | 理解、推理、生成文字/代码 |
| **本地推理运行时** | 把大脑装进自己电脑 | Ollama、LM Studio、vLLM… | 离线/隐私/控成本跑模型 |
| **编程 Harness / Agent** | 会改仓库的程序员助手 | Claude Code、Pi、DSH、Codex、OpenCode、Aider… | 读改跑测闭环 |
| **AI IDE / 插件** | 嵌在编辑器里的助手 | Cursor、Copilot、Cline、Trae、CodeBuddy… | 边写边改、可视化 |
| **云端自主 Agent** | 「丢工单，过会儿来 PR」 | Devin、部分 Codex Cloud、Replit Agent… | 长时间无人值守 |
| **个人助理 / 龙虾系** | 会操作电脑 + IM 派活 | OpenClaw、LobsterAI、QClaw、AutoClaw、WorkBuddy… | 办公生活自动化 |
| **记忆服务** | 外挂长期记忆 | Hindsight、Mem0、Honcho、OpenViking… | 跨会话记住事实与偏好 |
| **决策模型** | 专门做判断题 | **Jev** | 分类/打分/门禁，不写长文 |
| **协议与技能包** | 插线标准 | **MCP**、**Agent Skills**、**A2A** | 接工具、教流程、Agent 互叫 |
| **MCP Bridge（本地工具桥）** | 把本地工作区「借」给远端 AI | ShunCode Bridge、各类 MCP Server/桥 | 对话在云端客户端，动手在本地文件夹 |

关系示意：

```
用户提需求
  │
  ├─ 写代码（边看边改）──── IDE：Cursor / Trae / Copilot / Cline…
  ├─ 写代码（终端闭环）──── Harness：Claude Code / Pi / DSH / Codex / OpenCode / Aider…
  ├─ 丢任务等 PR ────────── 云端自主：Devin 类
  ├─ 生活/办公派活 ──────── 龙虾 / Hermes / WorkBuddy…
  ├─ 远端大脑 + 本地手脚 ── MCP Bridge：本地工作区 ←桥→ ChatGPT / Devin / Trae / Manus…
  ├─ 跨天记住偏好 ───────── 记忆层：Hindsight / Mem0 / …
  └─ Agent 内部高频判断 ─── Jev（选择题裁判）
         ↑
         协议：MCP 接工具 · Skills 教流程 · A2A 让 Agent 互相对话
```

编者认为：新手宜先会用**一个**编程入口（Cursor，或 Claude Code / Pi），再决定是否接触龙虾、记忆与 Bridge；Jev 更适合工程进阶阶段。

## 2. 大脑层：大模型与本地推理

### 2.1 大模型（只认「大脑」，不是完整产品）

| 厂商/系列 | 常见印象（测重点） |
|-----------|-------------------|
| **OpenAI（GPT 系）** | 生态广、Codex/ChatGPT 产品线完整 |
| **Anthropic（Claude 系）** | 长上下文与编程推理口碑强；Claude Code 深度绑定 |
| **Google（Gemini 系）** | 多模态与免费额度叙事；Gemini CLI 等 |
| **DeepSeek** | 性价比与代码能力；常配 **DSH** 等自家 Harness |
| **国内云模型**（通义 Qwen、豆包、混元、文心、Kimi、智谱…） | 中文、合规、与国产 IDE/龙虾绑定深 |

编者认为：同一颗「大脑」换不同 Harness，表现可以差一截——这也是社区常横向评测「谁的缰绳更好」的原因。

### 2.2 本地跑模型

| 工具 | 测重点 |
|------|--------|
| **Ollama** | 命令行友好，拉模型简单，适合个人本机试用 |
| **LM Studio** | 图形界面选模型、本机聊天 |
| **vLLM / 其它推理服务** | 更偏服务端高吞吐部署 |

它们**不是 Agent**：只负责「把模型跑起来」。要改文件、操作浏览器，通常还需要外面再套 Harness 或龙虾类产品。

## 3. 编程向：形态三分法

编者认为：先按**用户坐在哪干活**分类，比记二十个品牌名更重要。

| 形态 | 工作位置 | 自主程度 | 代表 |
|------|----------|----------|------|
| **IDE 嵌入** | 编辑器里 | 中：人看着改 | Cursor、Copilot、Windsurf/Devin Desktop、Cline、国产 Trae… |
| **终端 / CLI Harness** | 命令行窗口 | 较高：一轮里多步工具 | Claude Code、Codex CLI、Pi、DSH、OpenCode、Aider、Goose… |
| **云端自主** | 浏览器/看板 | 很高：丢任务等结果 | Devin、部分云 Agent、Lovable/Bolt 类「生成站」 |

编者认为：业界常见组合是 **日常用 IDE + 难题用终端 Agent**（两把刷子，不是非此即彼）。

## 4. 海外主流编程 Agent / IDE

### 4.1 Cursor —— AI 原生 IDE（测重点：编辑体验）

- VS Code 系分叉，聊天、补全、多文件改动都在编辑器里。  
- **擅长**：可视化 diff、边看边改、上手快。  
- **弱项**：编者认为，其内部循环的可拆改程度通常不如开源 Harness。  
- **适合**：大多数「想马上写业务代码」的人。

### 4.2 GitHub Copilot —— 装机量很大的插件助手

- 嵌在 VS Code / JetBrains 等。  
- **测重点**：补全默认项、GitHub 工作流整合、企业采购路径成熟。  
- **弱项**：编者认为，完整「自主改仓库」体验通常不如专用 Agent CLI。

### 4.3 Claude Code —— 成熟终端编程 Agent

- Anthropic 官方 CLI；权限模式、子 Agent、计划模式、MCP、Skills 等较全。  
- **测重点**：开箱体验、护栏、大仓库重构口碑。  
- **代价**：绑定 Claude 生态与订阅/API 成本。  
- **适合**：愿意为「稳、全」付费的终端主力用户。

### 4.4 OpenAI Codex CLI / 云端任务

- OpenAI 工作流下的终端 Agent；云端侧常强调并行任务、GitHub 原生。  
- **测重点**：OpenAI 模型与产品一体化。  
- **适合**：已在 ChatGPT/OpenAI 栈的团队。

### 4.5 Cline —— VS Code 里很常见的开源 Agent 扩展

- 免费扩展 + **自备模型密钥（BYOK）**；也可走本地模型。  
- **测重点**：成本可控、人在回路、不锁死厂商。  
- **适合**：想在熟悉的 VS Code 里跑 Agent，又不想只绑一家。

### 4.6 Aider —— Git 原生终端结对

- 老牌开源；强调 **repomap + 自动 commit** 的外科手术式改动。  
- **测重点**：和 Git 工作流咬合紧、改动可追溯。  
- **适合**：喜欢「每次改动都是清晰提交」的人。

### 4.7 OpenCode —— 星标很高的开源 Agent

- 多厂商模型（宣传常提 75+ provider）、开源许可叙事。  
- **测重点**：不锁模型、社区热度、可自建。  
- **适合**：要 Claude Code 类能力但不想厂商锁定。

### 4.8 Goose —— 基金会治理的通用 Agent

- 由 Block 等推动，后进入 Linux Foundation 相关 Agentic 基金会叙事。  
- **测重点**：不止写代码、可扩展工作流、厂商中立。  
- **适合**：要「通用特工」而不仅是写码器。

### 4.9 Devin / 原 Windsurf —— 本地编辑 + 云端自主

- Cognition 将 **Windsurf 并入 Devin Desktop**（公开报道中的 2026 叙事）：本地 IDE 与云端「工单→PR」打通。  
- **测重点**：异步自主、看板式多 Agent 会话。  
- **代价**：高阶档位通常较贵；可见性低于人自己盯着终端跑。  
- **适合**：团队把清晰工单外包给云端 Agent。

### 4.10 其它常见名字（知道定位即可）

| 名字 | 一句话 |
|------|--------|
| **Amp（Sourcegraph）** | 企业代码图/大仓推理向；按量计费叙事 |
| **Zed** | 高性能编辑器，可接 Agent；测重点在编辑器本身 |
| **Amazon Q Developer** | 亚马逊云开发者助手 |
| **Gemini CLI** | Google 系终端入口，常打免费额度牌 |
| **Kilo Code** | 开源/网关定价向的编码 Agent |
| **Crush（Charm）** | 终端 TUI 向、会话中切模型 |
| **Continue** | 曾流行的开源 IDE 助手；后续整合关系以官网为准 |

## 5. 开源与极客向 Harness（重点讲 Pi / DSH）

### 5.1 什么是 Harness？

大模型通常不会自己稳定地完成「打开项目 → 改文件 → 跑测试 → 看报错再改」。  
**Harness（缰绳/运行时）** = 工具权限 + Agent 循环 + 提示词 + 插件 + 沙箱 + 日志。  
编者认为：**同一模型，换 Harness，分数可以差一截**——这也是 Pi、DSH、Claude Code 常被放在一起评测的原因。

### 5.2 Pi —— 极简、多模型、透明（测重点：可控）

- 开源、Unix 味：统一模型层（常称 `pi-ai`）+ 终端 UI + 很瘦的系统提示 + 少量工具（读/写/bash/skills…）。  
- **测重点**：好理解循环；多厂商/本地模型；二次开发友好；部分公开评测里任务通过率不错。  
- **弱项**：开箱不如 Claude Code 花哨；权限默认较放开；复杂能力常靠自行拼 Skills。  
- 编者认为：想搞懂 Agent、换模型、抠成本时，可优先了解 Pi。

### 5.3 DSH（DeepSeek Harness）—— 插件化运行时（测重点：可换件）

- DeepSeek 方向的 Agent **运行时**；公开评测里常写 **DeepSeek Harness（DSH）**。  
- 设计上大量能力是**插件**（模型适配、工具、沙箱、会话，甚至主循环可替换；常见 Cordis 组合叙事）。  
- 产品侧常有 **DSH Desktop** 一类壳：宿主、白名单、插件市场，偏「可扩展底座」而不只是聊天框。  
- **测重点**：可插拔基础设施；DeepSeek 模型原生适配；部分同模型评测里成本/速度有竞争力。  
- **弱项**：概念较重、上手曲线通常高于 Pi；生态仍在快速演进。  
- 编者认为：要做 Agent **基础设施**或 DeepSeek 深度用户时，更值得看 DSH。

### 5.4 Pi vs DSH vs Claude Code vs Cursor（核心对比）

| | **Pi** | **DSH** | **Claude Code** | **Cursor** |
|--|--------|---------|-----------------|------------|
| 形态 | 薄终端 Harness | 厚插件运行时（可有 Desktop） | 完整商业 CLI | AI 编辑器 |
| 哲学 | 少即是多 | 一切皆插件 | 开箱即产品 | 嵌进写代码的屏幕 |
| 模型 | 多厂商友好 | DeepSeek 友好可扩展 | Claude 优先 | 产品策略定 |
| 定制深度 | 高（因为简单） | **很高**（循环都能换） | 中（钩子/配置） | 中低 |
| 上手 | 要懂一点循环 | 更要懂运行时 | 较省心 | 会 VS Code 就会 |
| 编者选型口诀 | 透明可玩 | 可换件底座 | 每天稳写码 | 编辑器里爽 |

编者认为：它们**都不是「小龙虾」**——主战场是写代码与工程任务；龙虾主战场是助理 + IM + 跨 App。

## 6. 国产 AI 编程工具

国内大致三条路：**插件**、**AI 原生 IDE**、**CLI/Agent 全家桶**。测重点常绑「云厂商生态 + 中文 + 合规」。

| 产品 | 厂商 | 形态印象 | 测重点 |
|------|------|----------|--------|
| **Trae**（含 SOLO / TraeWork 等） | 字节 | AI 原生 IDE + 自主模式 | 端到端 Agent、豆包生态、个人性价比叙事 |
| **CodeBuddy** | 腾讯云 | IDE + 插件 + CLI | 全流程开发、微信/腾讯云生态、设计稿/PRD 等周边 |
| **Qoder CN**（原通义灵码升级叙事） | 阿里 | IDE/插件/CLI/Work/Wake 等 | 工程感知、专家团、阿里云/高合规场景 |
| **通义灵码（Lingma）** | 阿里 | 经典插件向 | 行间补全、阿里云开发者习惯 |
| **文心快码 Comate** | 百度 | 插件 + IDE + 多 Agent | SPEC/规范驱动、私有化、政企 |
| **CodeGeeX** | 智谱 | 插件（开源叙事） | 多语言、翻译/补全 |
| **CodeFuse** | 蚂蚁 | 插件/企业 | 金融合规 |
| **Fitten Code** | 非十等 | 轻量插件 | 补全速度 |
| **华为 / 讯飞等** | 各厂商 | 插件或套件 | 硬件栈、语音等垂直 |

编者认为：国产很少「只复制一个终端」，更多是 **IDE + 云生态 + Agent 模式** 打包；选型宜先看已在哪朵云、要不要私有化，再比 Agent 强弱。

## 7. 「小龙虾」潮：OpenClaw 与国产 Claw

### 7.1 OpenClaw（俗称龙虾）—— 开源本地 Agent 引擎

- 能调用本机能力（文件、浏览器、命令等），并可从 Telegram / WhatsApp 等 **IM 远程派活**。  
- **测重点**：从「聊天」走到「执行」；Skills 生态；自托管自由度最高。  
- **为何火**：2025 末～2026 初全球传播；「养虾」成梗。  
- **为何「卸虾」**：配置难、Token 账单、误操作、安全与供应链讨论；部分机构限制办公网安装。  
- **定位**：底层引擎 + 社区，不是某一个品牌 App。

### 7.2 有道龙虾 LobsterAI —— 产品化「开箱虾」

- 网易有道桌面助理；内核可基于 OpenClaw；强调 Cowork。  
- **测重点**：GUI 降低门槛；办公文档/分析；国内 IM；开源与本地数据叙事。  
- **和野生 OpenClaw**：更偏安装、界面、通道、技能封装。

### 7.3 国内 Claw / 类龙虾产品谱系（广扫）

公开盘点里常见这些名字（功能与是否「真·OpenClaw 封装」因产品而异；亦有「独立架构但兼容 Skills」的说法）：

| 类型 | 代表 | 测重点（公开叙事归纳） |
|------|------|------------------------|
| **本地桌面派** | 智谱 **AutoClaw**、腾讯 **QClaw**、有道 **LobsterAI**… | 碰本地文件；安装相对「罐头化」；飞书/微信等接入 |
| **偏企业办公** | 腾讯 **WorkBuddy** | IM 覆盖广（微信/QQ/飞书/钉钉等叙事）；高危拦截、审计、工作区限制 |
| **云端 7×24 派** | 字节 **ArkClaw**、MiniMax **MaxClaw**、部分云主机方案 | 不碰或少碰本地盘；专家团/订阅更易控预算；适合内容/研究类 |
| **其它厂牌虾** | 百度 DuClaw、Kimi Claw、小米 MiClaw、讯飞等平替… | 各绑自家模型与入口（手机、搜索、办公套件） |

编者认为的本地 vs 云端选型要点：

- 要整理本机桌面/本地仓库 → 更看本地派。  
- 要人离开电脑后任务仍运行 → 更看云端派。  
- 要企业可控 → 看审计、白名单、是否禁止越权目录。

**计费常识**：原版 OpenClaw「软件免费、模型费用自付」——复杂任务账单可能很高；大厂虾多为**门槛费 + 包月积分/订阅**，降低配置门槛，但额度会用完。

### 7.4 龙虾 vs 编程 Harness

| | 龙虾系 | Pi / DSH / Claude Code / Cursor |
|--|--------|----------------------------------|
| 用户故事 | 手机喊一声，电脑把杂事办完 | 把这个仓库改对、测过、可合并 |
| 入口 | 桌面 App + IM | 终端 / IDE |
| 成功标准 | 跨应用办成事 | 代码正确可复现 |

## 8. 通用助理：Hermes 等

### 8.1 Hermes Agent（Nous Research）

- 自进化叙事：经验→Skills、跨会话记忆、定时任务、多平台网关（Telegram、Discord…）。  
- **测重点**：长期助理、多模型、可本机/廉价云；研究向学习闭环。  
- **和龙虾**：同属「生活在聊天入口的特工」；Hermes 更强调技能自改进与多执行后端。  
- **和 Pi/DSH**：后两者更「编程 Harness」；Hermes 更「通用代理产品」。

### 8.2 历史坐标（知道即可）

AutoGPT、BabyAGI 等早期「自主 Agent」demo → 今天的 Harness / 龙虾 / 云端 Devin，是同一条「让模型动手」路上更工程化的后代。

## 9. 决策层：Jev 不是聊天机器人

### 9.1 Jev 是什么？

**TypeSafe AI** 的 **System One 决策模型**：

- 输入：状态文本/结构 + **预先定义好的问题**  
- 输出：类型化答案  
  - **Choice**：固定选项里选一个（带概率）  
  - **Noul**：命题成立概率 0～1  
  - **Score**：量表打分  
- **不生成**长文、不写代码、不闲聊。

### 9.2 测重点与典型用法

- 高频、便宜、快（厂商宣称相对通用 LLM 有数量级优势，以官方为准）。  
- 输出可直接给代码设阈值（例如置信度低于某值则转人工）。  
- **用法**：工单路由、工具调用前护栏、模型路由、上下文压缩时「删不删这条工具结果」、合规检查。  
- LangChain 等有接入叙事：放在 Agent **中间件**，不替换主聊天模型。

### 9.3 和其它层的边界

| 需求 | 更相关的工具层 |
|------|----------------|
| 写功能、修 bug | Cursor / Pi / DSH / Claude Code… |
| 手机指挥电脑 | 龙虾 / Hermes… |
| 高频「选 A/B」「能不能执行」 | **Jev** |

## 10. 记忆层：让 Agent「跨天还认识你」

聊天窗口一关就忘，是默认行为。**记忆层**是外挂的「记事本/人格模型」。

| 方案 | 测重点（公开叙事） |
|------|-------------------|
| **Hindsight** | retain / recall / reflect；偏准确与结构化；可 MCP；基准成绩常被引用 |
| **Mem0** | 托管快、接入广；多端 Skills；偏「记忆即服务」 |
| **Honcho** | 辩证式「用户心智模型」，不只存事实 |
| **OpenViking** | 文件系统式分层上下文（L0/L1/L2），省 token 叙事 |
| **Holographic / RetainDB / ByteRover / Supermemory…** | 各走代数记忆、压缩、知识树、会话图等路线 |

Hermes 等产品常做成**可插拔 memory provider**（同时一般只启用一个外部提供方）。  
编者认为：新手可先不上记忆层；真的痛「每个会话都要重新自我介绍」再选。隐私敏感场景可优先考虑可自托管方案。

说明：Hindsight 是记忆服务；Hermes 是通用 Agent 产品——名称易混，品类不同。

## 11. 协议与桥接层：MCP / Bridge / Skills / A2A

协议解决「怎么插线」；**Bridge 是把协议做成产品**的一类形态。先分清标准，再看桥。

### 11.1 三个开放标准（解决的问题不同）

| 协议/标准 | 一句话 | 类比 |
|-----------|--------|------|
| **MCP**（Model Context Protocol） | Agent **接工具与数据**的统一插线 | USB：数据库、GitHub、浏览器、本地文件… |
| **Agent Skills**（agentskills.io） | 教 Agent **怎么做一类活**的文件夹（`SKILL.md` + 脚本/资料） | 菜谱 + 厨具说明 |
| **A2A**（Agent-to-Agent） | **Agent 与 Agent** 发现彼此、委派任务 | 同事之间派工单 |

互补用法：编排 Agent 用 A2A 找专家 Agent → 专家用 MCP 查库/改票 → Skills 规定「事故处理五步怎么走」。

MCP 里固定有两个角色：

| 角色 | 干什么 | 例子 |
|------|--------|------|
| **MCP Server（服务端）** | 在本机或内网**暴露工具**（读文件、跑命令、查库…） | 文件系统 MCP、GitHub MCP、**各类 Bridge 背后的服务** |
| **MCP Client（客户端）** | 在对话里**调用**这些工具 | Claude Desktop、Cursor、ChatGPT（支持 MCP 时）、Devin、Trae、Manus、WorkBuddy… |

### 11.2 MCP Bridge（本地工具桥）—— 一类独立产品

#### 它是什么？

**MCP Bridge / 本地工具桥**：在本机运行的一座「桥」，把**当前编辑器/工作区里的工具与文件夹**，按 MCP 协议暴露给**外部远程客户端**。  
典型产品文案会写成：「将当前工作区工具连接到 ChatGPT 或其他远程 MCP 客户端。」

人话版：

- **大脑**可以在云端（ChatGPT、Devin、Manus、Trae、Qwen 客户端、WorkBuddy…）  
- **手脚**留在本地已打开的项目目录里  
- **对话输入仍在外部客户端**；工具调用记录出现在 Bridge 面板里  

它**不是**又一个聊天机器人，也**不是**完整龙虾/完整 IDE；它是 **接线层产品**。

#### 典型结构

```
┌─────────────────────┐         MCP          ┌──────────────────────────┐
│ 远程 MCP 客户端      │ ◄──────────────────► │ 本机 MCP Bridge / Server │
│ ChatGPT / Devin /   │   工具调用与结果      │ 绑定：已打开的工作区      │
│ Trae / Manus / …    │                      │ 权限：通常限定该文件夹    │
└─────────────────────┘                      └──────────────────────────┘
         │                                              │
    在此打字聊天                                  真正读写本地文件
```

常见界面能力（产品各异，模式相近）：

- **启动 Bridge**：本机开始监听，等待客户端连上  
- **复制提示词 / 连接说明**：把一段配置或提示贴到远端客户端，完成配对  
- **打开教程**：说明支持哪些客户端、如何授权  
- **调用日志面板**：远端每次工具调用会显示在这里，便于审计「它到底动了什么」

#### 测重点（选型时看这些）

| 维度 | 说明 |
|------|------|
| **作用域** | 默认是否只限「当前已打开工作区」，还是能扫整盘（后者风险大） |
| **客户端覆盖** | 是否明示支持 ChatGPT、Devin、Trae、Manus、WorkBuddy、Browser Use、各类国内 Agent 等 |
| **鉴权与超时** | 连接是否有令牌、是否会过期、断线是否停写 |
| **可观测性** | 工具调用是否逐条可见、可否拒绝单次危险操作 |
| **与宿主 IDE 关系** | 常附着在某一编辑器（如 ShunCode Bridge 之于 ShunCode）；也有独立通用 MCP Server |

#### 和相近品类怎么区分？

| 对比对象 | 差别 |
|----------|------|
| **Cursor / Trae 等 AI IDE** | IDE 是「聊天+改代码」一体；Bridge 是「聊天在别处，改代码能力借出去」 |
| **Claude Code / Pi / DSH** | Harness 自己带着循环和工具跑；Bridge 通常**不负责**完整 Agent 循环，只当工具后端 |
| **龙虾 / OpenClaw** | 龙虾多是本机常驻助理 + IM；Bridge 强调 **MCP 标准对接多品牌远端客户端** |
| **普通 MCP 插件** | 在 Cursor 里「添加 MCP」是客户端去连某个 Server；Bridge 产品则把「本机当 Server、外面一堆 Client」做成一键体验 |
| **浏览器自动化（Browser Use 等）** | 管的是浏览器；Bridge 管的是**工作区/本地工具**（二者可同时出现在同一客户端生态里） |

#### 生态里常见的「远端客户端」类型

| 类型 | 例子（公开生态中常见） | 挂 Bridge 后多出来的能力 |
|------|------------------------|--------------------------|
| 通用对话客户端 | ChatGPT、部分 Arena / 评测台 | 用网页聊，却能读写本地项目 |
| 云端工程 Agent | Devin、Manus 等 | 远端规划 + 本地落盘改代码 |
| 国产 AI IDE / 助手 | Trae、WorkBuddy、Qwen 系客户端、Agnes AI、Z.ai 等 | 不换本地 IDE，也能让另一家客户端动同一工作区 |
| 专用自动化 | Browser Use 等 | 浏览器自动化 +（经 Bridge）本地文件协同 |

> 具体支持名单以各 Bridge 产品界面为准；名单会随版本增减。

#### 安全与使用边界（编者认为比功能更重要）

1. **默认当作「给云端大脑开了本机文件夹权限」**——只连信任的客户端，工作区不要指向整盘或密钥目录。  
2. **看清作用域**：好的 Bridge 会写明「仅当前工作区」；越权范围应视为风险信号。  
3. **用完可关**：长时间挂着等于持续授权；任务结束宜停止 Bridge。  
4. **日志当审计**：面板上的工具调用列表，是判断「有没有乱删乱改」的第一现场。  
5. **公司环境**：机密代码经 Bridge 暴露给云端客户端，可能触及合规红线——宜先遵循组织安全策略。

#### 代表形态举例

- **编辑器附带 Bridge**：如 **ShunCode Bridge**——把当前工作区工具接到 ChatGPT 或其他远程 MCP 客户端；界面常见「启动 Bridge / 复制提示词 / 打开教程」，并展示可对接的客户端。  
- **独立 / 通用 MCP Server**：只提供文件系统、终端、浏览器等标准 Server，由任意 MCP 客户端配置连接（偏开发者手动配）。  
- **浏览器侧桥**：如各类「Chrome MCP Bridge」，把浏览器标签页能力暴露给 Agent（和「工作区 Bridge」同属桥接家族，作用域不同）。

### 11.3 编者认为的上手顺序

| 阶段 | 建议 |
|------|------|
| 入门 | 在 Cursor / Claude 里**添加一个现成 MCP**（例如文档或数据库），感受「工具调用」 |
| 进阶 | 需要「云端某 Agent + 本地某项目」时，再开 **MCP Bridge**；先小文件夹试 |
| 团队 | 用 **Skills** 固化流程；多 Agent 协作再上 **A2A** |
| 工程化 | 自写 MCP Server、配网关与审计，而不是只依赖一键 Bridge |

### 12.2 编者认为的 30 秒选型口诀

1. **写代码、要界面** → Cursor / Trae / Copilot

6. **Agent 里狂做判断题** → Jev  
7. **跨天记住偏好** → 记忆层  
8. **对话在 ChatGPT/Devin/Manus 等，改的是本地已开项目** → **MCP Bridge**（先限小工作区、看调用日志）

## 13. 新手学习路线

### 第 0 周：只建立分类

能口头区分：IDE vs 终端 Harness vs 龙虾 vs Jev vs 记忆 vs **MCP Bridge**。

### 第 1 周：选定一个编程入口练手

- 图形优先 → **Cursor**（或国产 Trae 等）  
- 终端 + 理解原理 → **Pi** 或 **Claude Code**  
练习：**解释仓库 → 小改 → 说明改动**；配合 Git。

### 第 2 周：知道龙虾潮在吵什么

读 OpenClaw / 有道龙虾 / 一两家大厂虾的定位即可。  
若试用：工作目录授权、备份、勿在机密内网随意安装。

### 第 3 周：可选加深

- DeepSeek / 插件运行时兴趣 → **DSH** 文档  
- 真痛「没记忆」→ Mem0 或 Hindsight 其一  
- 开始写护栏/路由 → **Jev**  
- 接公司系统 → **MCP**；沉淀团队流程 → **Skills**  
- 需要「云端某客户端动本地项目」→ 试用 **MCP Bridge**（小目录、看日志、用完即关）

### 做减法原则

编者认为：同一时期**主力入口不宜超过两个**（例如 Cursor + 一个终端 Agent）。  
龙虾、编程 Agent、Bridge 可以并存，但学习时不要当成同一种软件。

## 15. 附录：常见软件作用一览

> 编者按：本节按 **Agent / Hermes / Code** 三类，整理公开生态中常见软件的「作用」与「能做什么」，便于对照前文品类。  
> 不绑定任何个人电脑安装路径或版本号；具体以各产品官网与本机实际为准。

### 15.1 Agent（AI 助手 / Agent 壳）

| 软件 | 作用 | 能做什么 |
|------|------|----------|
| **DSH Desktop** | DeepSeek Harness 体系常见的桌面宿主壳 | 跑宿主与插件、在策略允许范围内使用本机工具能力 |
| **Cursor** | AI 原生代码编辑器（VS Code 系） | 打开项目、用自然语言让 AI 读改代码、看 diff、辅助跑命令 |
| **Claude Desktop** | Anthropic 官方桌面客户端 | 与 Claude 对话；通过 MCP 接本地/远程工具 |
| **Ollama** | 本地大模型运行时 | 本机下载并跑开源模型；离线或控成本地聊天/写代码 |
| **OpenCode** | 开源向 AI 编程桌面/终端产品 | 多模型编程助手：解释代码、改文件、做小任务 |
| **LobsterAI（有道龙虾）** | 桌面级个人助理 Agent（OpenClaw 生态） | 办公派活：文档/分析/检索；可经 IM 远程指挥 |
| **AgnesCode / Agnes AI** | AI 编程 / 助手客户端 | 对话式写代码、改项目 |
| **Antigravity** | Google 系 AI IDE / Agent | AI 辅助编程、Agent 式完成开发任务 |
| **Freebuff** | Codebuff 系 AI 编程桌面 | 用自然语言驱动代码相关任务 |
| **OpenSquilla** | Agent / 助手桌面 | 通用助理式对话与工具调用 |
| **Xiaomi MiMo** | 小米侧 AI / 代码助手 | 对话、代码辅助；接小米模型生态 |
| **ZCode** | AI 编程客户端 | 项目内问答、生成与修改代码 |
| **Trae / TRAE SOLO / Work** | 字节系 AI IDE | IDE 内 Agent 编程、自主任务、多端工作台 |
| **CodeBuddy** | 腾讯云 AI 编程助手 | 补全、Agent 编程、对接腾讯云等生态 |
| **Qoder / QoderWork** | 阿里 Qoder 相关产品 | Agentic 编程与办公向工作流 |
| **WorkBuddy** | 办公/工作流助手 | 文档整理、会议相关、企业 IM 场景派活 |
| **WeFlow** | 流程 / 自动化向工具 | 把重复流程自动化、编排步骤 |
| **AutoClaw** | 龙虾/Agent 运行时（智谱等方向常见） | 本机 Agent 执行、Skills；可与审批/编排类产品联动 |
| **ShunCode** | AI 代码助手 / IDE 向产品 | 写改代码；可经 **ShunCode Bridge** 把工作区接到远程 MCP 客户端 |
| **Cua** | 电脑操控 / Agent 驱动组件 | 为 Agent 提供桌面操控类能力（偏驱动层） |

编者认为：若同一台电脑上「AI 编程壳」装得过多，日常通常只需 **2～3 个主力**（例如 Cursor 写代码 + 一个宿主/助理 + 可选 Ollama）；其余可归档以减少干扰。

### 15.2 Hermes（通用自进化 Agent）

| 组件 | 作用 | 能做什么 |
|------|------|----------|
| **Hermes Desktop** | Hermes Agent 的图形界面 | 用桌面端与自进化 Agent 对话、管理连接与会话 |
| **Hermes CLI** | 同一套 Agent 的命令行入口 | 终端交互、切换模型、网关/定时等高级能力 |
| **用户数据与配置** | 保存连接、后端归属等 | 备份与迁移时保留配置（具体目录因安装方式而异） |
| **与其它 Agent 运行时联动** | 审批 / 连接 / 编排（视集成而定） | 敏感操作可走审批流，而不是当作普通聊天壳 |

编者认为：Cursor 侧重「打开仓库边写边改」；Hermes 侧重长期助理、技能沉淀、多通道与编排——不宜混为一谈。  
若听到易混名称 **Hindsight**，那是第 10 章的记忆服务，不是 Hermes。

### 15.3 Code（开发工具链 / IDE）

#### 编辑器 / IDE

| 软件 | 作用 | 能做什么 |
|------|------|----------|
| **Cursor** | AI IDE | 写业务代码、AI 结对、多文件重构 |

## 收束：五句话版全景

1. **模型是大脑**；Ollama 一类只是把大脑跑在本地。  
2. **写代码**看 IDE（Cursor/Trae…）和 Harness（Claude Code/Pi/DSH/OpenCode…）；编者认为 **Pi 偏极简，DSH 偏可换件**。  
3. **小龙虾**是助理+IM+本机执行浪潮；有道龙虾是产品虾，OpenClaw 是引擎，大厂各做本地/云端方案。  
4. **Jev** 只做判断题；**记忆层**解决跨会话；**MCP/Skills/A2A** 是标准；**MCP Bridge** 是「远端大脑 + 本地手脚」的产品化桥。  
5. 编者认为：新手宜**先精通一个编程入口**，再按需加龙虾、记忆、Bridge 与 Jev——全而广是为了认路，不是为了全装。
