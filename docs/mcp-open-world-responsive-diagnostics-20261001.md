修复后，小屏打开应用时给内容区留足空间；在原生问答中收起会话列表，点击“历史与文件”可以恢复导航。窄屏窗口铺满可用区域，顶部控件允许换行。

正式构建实机结果：

| 视口 | 回复区宽度 | 验收 |
|---|---:|---:|
| 320 × 844 | 264.8px | 7/7 |
| 390 × 844 | 335.2px | 7/7 |
| 768 × 844 | 367.5px | 7/7 |

每组检查：独立验收会话正确、输入框完整可见且可输入、回复区至少 240×120px、返回历史后导航可用、重新打开仍有既有上下文回复、返回世界按钮可访问、切换过程中没有发问题或取消会话。

这是 **Desktop WebView 的视口模拟**，不是手机真机或软键盘、横屏、触控的全面验收。

同轮复验：世界入口 **21/21**、历史与文件 **19/19**、原生问答重开 **3/3**、保全检查 **9/9**。连同窄屏检查，合计 **73 项通过**。

## 3. 终端问题：诊断更明确，但尚未解决

为测试进程添加了独立诊断记录，捕获到 worker 退出码：

`3221225477 = 0xC0000005 / STATUS_ACCESS_VIOLATION`

这说明捕获到的是 **原生访问违例**，不是简单的 JavaScript 断言失败或测试超时。尚没有足够证据确定具体故障 DLL／原生调用位置。

还对 node-pty 自带的 `useConptyDll` 模式做了测试进程内的对照实验，没有修改依赖包或生产配置：

- 两次组合运行均为 **48/50，2 项超时**，没有在这两次运行中重现 worker 崩溃。
- 独立 I/O 诊断能得到真实命令输出，但两个终端都发出退出事件后，诊断 Node 进程仍持续不退出；超过 100 秒后停止了这个独立诊断任务。
- 因此该候选模式 **未采用、未上线**。

测试夹具改为不加载用户 PowerShell profile，并使用非交互模式，减少个人配置和交互历史对测试的影响；没有修改用户的实际终端配置。

原后端在这一夹具下再次组合运行：**计划 50 项，44 项通过，1 个 worker 异常退出，整组未完成**。TypeScript 检查通过，但这不能替代失败的运行时验收。
