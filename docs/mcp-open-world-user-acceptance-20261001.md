# Open World 用户端验收与修复（第一批）

日期：2026-10-01。

## 结论与范围
本轮把验收重心从底层 API 转到真实 Desktop 页面里的 Open World：实际切换视图、点击园中入口、打开聊天坞、切换测试记录、打开附件预览，并检查错误提示和界面遮挡。

**这是第一批缺陷修复，不是“所有用户端功能已经完成”。** 历史 Agent 产物列表、世界内 Agent 回复闭环、实际回退和任务执行仍存在待办。新附件预览通过，不能代替用户那份历史产物的原入口验收；网址渲染成链接，也不能代替外部站点可访问性验证。

测试通过 CDP 在真实页面派发 DOM/Pointer 事件并核对渲染结果；不是只调用后台接口，也不是人工逐像素点击。窄屏、键盘全流程、系统文件选择器及所有外部浏览器行为尚未覆盖。

## 已定位并修复

### 1. 园视图运行错误
- `GardenView` 使用 `useMemo` 却没有导入。新增组件运行测试直接复现 `useMemo is not defined`；原来的静态检查未捕获。
- `CenterStage` 向园传递 `handleSendMessage`、`handleSearchMemory`，但未接收这两个参数。真实运行捕获 `handleSendMessage is not defined`，现已补齐。

### 2. 点击功能入口却不显示
- 嵌入面板原先只在主视图（ATI）分支渲染。从园或其他视图打开应用，状态已变但界面不可见。
- 现在嵌入应用独立于当前视图渲染；应用打开时暂时隐藏底层场景，返回后再恢复场景。
- 实际截图还发现园径、名牌、寄信栏覆盖聊天应用；已通过上述互斥显示修正，而不只是提升层级遮住问题。
- 月/舱的系统状态、灯的会话列表、门的回退列表改为打开对应面板，不再只弹“去别处找”的说明。
- 补齐舱的交互登记。
- 任务、远程连接和插件市场不可用时，入口明确标注并禁用。**这不是这些服务的执行验收通过。**

### 3. 消息、内容和附件
- 普通 HTTP(S) 网址和 Markdown 网页链接在聊天坞中显示为真正的链接。
- 缺失地址、`#`、不安全协议不再伪装成可打开的附件。
- 本地聊天附件可在世界内预览文本和静态 HTML；图片预览代码支持 PNG/JPEG/GIF/WebP，但本轮没有逐格式实测。
- HTML 预览使用隔离 iframe，禁用脚本及外部资源；**不等于交互式 HTML 应用已验收**。
- 未支持的格式提供下载后打开的提示；没有声称 Office/PDF 内嵌预览已完成。
- 不存在的附件显示明确错误，不是点了没有反馈。
- 下载请求核对了真实文件字节与 attachment 响应头；没有把收到 HTTP 200 当作本机文件已成功保存。
- 再点当前记录不再把消息清空到下一次轮询；切换其他记录时清理旧预览。
- 预览自动滚到可见位置，并暂时收起输入区；消息区独立滚动，调整高度以保留主要操作按钮。

### 4. 去除误导与精简
- 独立聊天页原先断线时展示硬编码的示例对话、示例报告附件（地址为 `#`）。已移除这些数据，断线显示真实状态并禁用提交。
- 这证明代码中存在不可打开的演示报告，**不能据此断言用户遇到的一定是该示例**。
- 修复独立页删除待发送附件、切换记录时未同步清理上传引用的问题；尚未完成系统文件选择器端到端复测。
- 聊天坞默认“本机”改为“记录”、按钮改为“保存记录”，明确不会在这里自动生成助手回答。
- “官方聊天”改为“转到桌面会话”，注明回复在桌面会话中，不把转交当作世界内问答完成。
- 广播、全会话、导出等入口默认收进“更多投递方式”。
- 移除园名牌里重复的关系说明和没有功能的世界包操作按钮，收敛“随时能回”等过度承诺。

## 后续顺序
1. 优先修复历史产物入口与当前会话/产物契约兼容性，用实际历史文件确认“找得到、点得开、内容正确”。
2. 打通世界内一对一问答，不再以跳到桌面回答代替世界内交付。

4. 最后恢复隔离任务链路与其他低频入口；默认界面只保留已经可靠的高频操作。

验收口径：入口出现、点击可达、实际功能完成、错误可解释、结果可重开，分别记录；不再用累计静态断言数代替用户体验完成度。
