# Open World：稳定性与回退入口验收

日期：2026-10-01

## 本轮结论

已部署并重启验证 **v2.78 / build `0abe5e9b55`**。本轮新增修复聚焦上传竞争、回退入口和侧栏平台兼容；此前完成的历史重开、原生问答只是复验，不重复计为新功能。

### 1. 上传：从真实失败到世界内打开成功

- Windows 的流写入完成，不等于文件句柄已经关闭。上传现在等待关闭后才提交文件。
- 首次实机并发上传仍复现了 `EPERM`：两个请求一个成功、一个失败。因此没有把早先单元测试通过当作最终完成。
- 补充同目标文件的提交排队，以及 Windows 短暂文件占用的有限重试；只重试特定占用错误，累计等待最多约 785ms。
- 不通过删除原文件绕过锁定。新增测试覆盖永久占用时保留原内容、清理临时文件、释放队列，以及非占用错误不重试。
- 最终实机两个并发上传请求均成功；随后在 **Open World → 会话历史 → 查看工作区文件** 找到并打开文件。世界内显示内容与磁盘 SHA-256 一致，没有部分文件或临时文件残留。

这是“真实上传接口＋世界内发现和打开”的验证，不冒充拖拽上传界面测试。测试文件只写入既有独立验收目录。

### 2. 回退：修复假空列表，执行保持不可用

- 实机发现园景入口使用另一套旧渲染器，虽然统计有快照，列表却显示“暂无锚点”，还引导用户去聊天。
- 已统一到读取真实 `timeline.points` 的时间轴；最终世界内能够看到既有快照。
- 删除跳去聊天执行 `/rewind` 的引导、自我重复导航，以及每条历史旁重复的不可用按钮。
- 页面明确说明：**会话绑定与旧插件兼容性尚未验证，回退暂不可执行。**
- 桥接执行路径也拒绝回退，不只是把按钮变灰；不会先报成功，再尝试命令或 DOM 回退。
- 未对任何真实会话执行回退，也未全局禁用 Open World 之外的旧插件。

**这完成的是安全收口和只读历史修复，不是回退执行能力修复。**

### 3. 侧栏：已修复部分缺陷，未宣称全绿

- 修正 Windows 终止信号的调用方式；新增 5 项注入测试。
- 修正 Windows 目录链接测试夹具及清理，并验证链接外目录没有被删除。
- 隔离浮窗测试的 jsdom 存储，避免前一测试的持久化尺寸污染后一测试。
- 文件、占用重试、信号和浮窗专项合计 **27/27 通过**；TypeScript 检查、bundle 均成功。
- **真实 ConPTY 批量测试仍出现过 `AttachConsole` 和 worker 异常退出。完整侧栏套件尚未得到全绿结果。**
