# Open World＋侧栏：GitHub 发布前审查

日期：2026-10-01。范围：用户选择的 Open World 与侧栏修复。

## 结论：本轮不放行稳定版发布

**核心体验已成型，但工程交付尚未收口，不能确认“代码没有问题”。**

- **稳定版／正式 Release：不建议发布。** 有可复现的运行时失败和独立环境测试失败。
- **开发分支／私有 Draft PR：可以作为下一阶段的审查方式，但应先整理仓库、提交文件和已知限制。** 不建议把当前工作区原样推送。
- **公开预览版：不必等所有规划功能完成，但必须明确未支持项，完成凭据与历史检查，并处理默认启用能力的高风险问题。**

本轮没有提交、推送、打 tag、发布 npm 包、安装依赖或重启 Desktop；未更改生产配置、provider、model 或 key。也没有修改产品源码。

## 一、主要发现

### 1. 阻断稳定版：真实终端仍有原生崩溃

此前捕获到测试 worker 退出码 `0xC0000005`（原生访问违例）。最近的组合运行计划 50 项，只完成 44 项通过，随后 worker 异常退出。

单独运行 20 项通过，不能替代组合运行失败。候选 ConPTY DLL 模式也有测试超时及进程退出挂起，不能作为已验证替代方案。

**放行条件：** 明确修复或安全隔离失败路径；重复组合回归不再异常退出；验证真实终端创建、输入、关闭、终止与资源回收。仅增加超时、减少并发或忽略 worker 错误不算完成。

### 2. 阻断可复现交付：Open World 依赖目录外的 RRA 原型

相关位置：
- `dsh-open-world/test/smoke.mjs:151-152`：直接断言相邻 `../rra-proto` 存在。
- `dsh-open-world/test/smoke.mjs:549` 附近：缺少原型后继续访问结果，发生异常。
- `dsh-open-world/bridge/rra-adapter.mjs`：包含相邻目录探测。

本轮将 Open World 的 **105 个工作区 Git 候选文件**复制到独立验收目录，不带原目录旁的 `rra-proto`，运行冒烟测试。结果：**退出码 1，至少 4 条断言失败，随后 TypeError，整组没有完成。**

这是工作区源码快照测试，不冒充真正的远程 Git clone。它已经证明：**现有完整工作区的 722 项通过，不能直接外推为“只下载这两个项目也能通过”。** 这也不等于 Open World 所有运行功能都会崩溃；首先暴露的是依赖边界和默认测试门禁不可复现。

**放行条件：** 明确依赖交付方式，或将可选 RRA 集成与基础测试正确拆分；基础功能在独立环境可验证，可选集成的未验证状态必须显式保留。

### 3. 安装兼容风险：侧栏防重复挂载配置被删除

`dsh-better-sidebar/cordis.patch.yml` 的工作区差异删除了原有 `disabled: !!js ...` 防重复挂载表达式，但同一文件第 33–44 行仍声称有此保护。

与聚合插件共同安装时，存在重复挂载和路由重复注册的风险。此次发现基于明确的配置差异；**没有在用户当前 profile 上实际制造重复挂载来验证崩溃。**

**放行条件：** 确认删除原因与新旧宿主兼容要求，补充“单独安装／聚合插件先安装／反向顺序”的隔离挂载测试，再决定兼容实现。不要未经验证直接恢复旧表达式到正在使用的环境。

### 4. 仓库边界尚未整理

- Open World 位于外层 `D:/dsp` 仓库，当前分支为 `main`，没有配置 Git remote。
- 侧栏是独立嵌套仓库，分支为 `fix/turn-tail-deliverables-20261001`。
- 外层记录侧栏为 **gitlink（模式 160000）**，不是普通目录；只推外层仓库不会带上侧栏未提交的修复。
- 外层还有多个不在本次范围内的项目修改。
- 两个项目都有关键未跟踪文件，包括新模块、测试与测试启动脚本。

**不要使用 `git add .` 或把整个 `D:/dsp` 打包上传。** 需要分别确定 Open World 仓库去向、侧栏现有仓库／fork 的提交方式，并逐项确认提交清单。若公开外层仓库，还必须检查其已有历史，而不只是这次新增文件。

### 5. 文档与分发准备不足

- Open World README 仍主要描述旧系统壳，未清楚交代当前原生问答、只读回退、文件版本与格式限制。
- 安装示例固定为本机 `D:\dsp`，不适合直接作为独立下载后的安装说明。
- Open World package 声明 MIT，但项目目录没有独立 LICENSE 文件；公开独立分发前应确认授权并补齐。
- 追加页脚修正仍缺正式构建的界面验收；此前因用户正在使用而没有强制刷新或重启。

### 6. 低优先级代码卫生

`git diff --check` 在 Open World 返回非零，发现：
- `client/modules/styles.js:441` 尾随空格。
- 对应生成文件 `client.js:1454` 尾随空格。

侧栏的差异空白检查通过。此项不是运行时崩溃原因，应随源码及生成产物一起清理。

## 三、安全审查边界

本轮检查 Git 工作区候选文件、部分相邻连接文档、远端地址是否含凭据；报告不输出可能的密钥值。侧栏远端地址未发现内嵌凭据。

**未完成：** Git 全历史密钥扫描、依赖漏洞公告审计、全部代码逐行安全审计、全平台验证、实际 GitHub clone 后安装及打包产物验收。

因此，未命中规则不等于不存在密钥、隐私数据或安全漏洞；尤其不能据此公开整个外层仓库及其历史。

## 四、你现在该做什么

**现在不用手动上传，也不需要更改模型、密钥或重装环境。**

建议顺序：
1. 先处理终端稳定性、独立依赖边界、防重复挂载三个主要问题。
2. 补齐 README、许可证、已知限制和可重复运行的检查流程。
3. 整理两个仓库的提交清单，完成历史／凭据审查。
4. 通过后再确认 GitHub 仓库归属、公开或私有；优先走开发分支与 PR，不直接发稳定版。

回退执行、任务兼容、PDF/Office 内嵌阅读等未完成能力可以在开发预览版明确标注，并不要求所有规划功能齐全才上 GitHub。但现有失败不能隐藏或宣称已经解决。
