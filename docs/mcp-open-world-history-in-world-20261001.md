日期：2026-10-01

## 结论

**已在 Open World 内实现并验证历史内容浏览，不再用桌面文件列表代替世界内交付。** 当前部署构建为 `b6b7da78b0`，版本仍为 v2.78。

使用路径：**开放世界 → 事件 → 在聊天坞继续 → 历史会话 → 选择会话**。

- 从真实 Session 记录中列出“成功写入”或“明确交付”的文件。
- 文件直接在原窗口预览；返回后仍在原会话，已经加载的历史页保留。
- 提供“加载更早记录”，不把第一页没有文件说成整段历史没有内容。
- 对命令行生成、没有登记到产物记录的文件，可进入“查看工作区文件”，筛选目录、进入子目录、打开和返回。
- 工作区列表明确说明“未必由此会话生成”，不混淆来源。

## 实际操作验证

通过 CDP 在真实 Desktop 页面驱动 DOM 交互，不是人工逐像素点击，也不是只请求 API：

1. 在世界聊天坞打开历史会话列表，选择既有真实会话。
2. 打开该会话登记的 `D:/dsp/_scratch/dsh-550c-boot/src/client.js`，在世界内显示 21,955 个文本字符，并核对哈希。
3. 返回会话，连续加载 5 页更早记录；列表扩展到 9 个已登记文件。
4. 展开只读会话文字；没有发送消息或调用 Agent。
5. 进入会话的 `D:/dsp` 工作区，浏览子目录再返回，筛选 `dsh-architecture.html`。
6. 在世界内实际预览该 HTML，查看截图确认有真实图形内容；关闭预览后筛选条件仍在，再返回历史记录时分页结果仍在。
7. 临时拦截浏览器中的单次文件 stat 响应，注入“文件不存在”；界面明确报错。恢复请求后点击“重试”，成功恢复预览。没有删除任何真实文件来制造失败。
8. 最终停留在世界内 HTML 预览，可直接查看。

## 为什么这样实现

- **不另建文件库、不复制 Session 历史**：复用 `session/list`、`session/page` 与官方 `workspaceFiles/list/stat/readBytes` 接口。
- **不猜产物**：仅依据明确交付事件或已成功的受支持写入操作；不从助手文字中随意提取文件名。
- **不新增一堆入口**：接在现有聊天坞内，“本地记录”仍保留，低频文件浏览从所选会话进入。
- **只读浏览**：没有新建 Agent 会话、发送 prompt、执行任务、回退、恢复或删除历史内容。
- **不修改官方安装包**：只修改 Open World 插件源文件与测试，再由原构建器合成 `client.js`。

## 本轮捕获并修正的问题

- 初版采用可选服务注入，代码测试通过但真机文件服务未就绪。改为经过实测的官方 HTTP RPC，并正确解码原生 multipart 二进制响应；没有把 HTTP 200 当成文件已打开。
- 原聊天坞在历史浏览时仍会轮询本地消息并标为已读。现在进入历史模式就暂停本地轮询，且在途请求也不会在隐藏界面签收消息。
- 实际截图显示预览底部被外层滚动区域裁掉。已让预览适配面板剩余高度，并增加边界检查。
- 测试最初把后台本地聊天的已读请求混入历史接口审计；随后分别记录请求来源，并修复了上述后台签收。最终历史验收没有观察到额外 POST。

## 支持范围与限制

- 实测通过：本地文本/源代码、静态 HTML、目录浏览、历史分页、返回状态、错误反馈与重试。
- 图片预览有实现，但本轮未逐格式实测；PDF、Office 等目前提供下载后打开提示，**未实现并验收内嵌预览**。
- HTML 采用隔离 iframe，禁止脚本及外部资源。页面自身的主题切换、导出等交互按钮不会运行；这不是交互式 HTML 应用的完整验收。
- 读取的是**当前磁盘文件，不是生成当时的历史快照**。文件移动或删除时不会伪造内容；历史记录保留。
- 预览上限 8 MB；未知大小或不完整响应会拒绝自动预览。敏感凭据文件名被拦截。
- 目录浏览沿用官方工作区边界，界面不允许目录名引入上级跳转或其他根目录；符号链接在此入口不打开。已登记文件按原路径交给官方文件读取接口处理，未另扩展宿主权限。
- 下载字节已核对，**没有把它算作操作系统原生保存对话框和保存后重开验收**。
- 尚未覆盖全部 104 个会话、所有旧格式日志、窄屏与完整键盘流程，也未确认用户最初所指的每一个具体坏文件或外部网址。

## 下一步：世界内问答

已复核现有代码：本地记录不会生成助手回复；“转到桌面会话”路径仍调用 `onInject(text)`，没有在该窗口实现完整的回复回流，也没有等待这条转交路径完成。因此，**历史浏览通过不能替代世界内问答通过**。

下一项必须完成：
1. 显式对应原生 Session，不再依赖“当前桌面会话”的隐含目标。
2. 发送、处理中、失败、完成都有可见状态；回复回到同一世界窗口。
3. 验证连续追问的上下文，以及退出世界后再次打开仍能找到对话和产物。
4. 仅用隔离会话做自动测试；任务调度继续保持停用。

上轮侧栏全量回归的 14 项失败及 1 个异常、回退兼容性和具体外链仍是独立待办，本轮没有将它们改写为通过。
